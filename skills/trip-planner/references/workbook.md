## 1. Принцип

`trip_data.json` хранит исходные данные (цены в исходной валюте, количества, выбор); книга `Расчеты_<Страна>.xlsx` собирается из него скриптом `build_workbook.py` и считает рубли формулами. Пока книгу не правили вручную, любое изменение делается так: правка `trip_data.json` → `build_workbook.py` → показать пользователю итоги и что изменилось.

Пример файла — `$SKILL/assets/trip_data_example.json` (фрагмент поездки в Японию).

## 2. Схема trip_data.json

Ключи на английском, значения на русском. Даты — `YYYY-MM-DD`. Числа — числом; простую арифметику можно записать формулой-строкой (`"=172952+1620"` — так видно, из чего сложилась цена). `selected` — строго `"Да"` или `"Нет"`.

```jsonc
{
  "schema_version": 1,
  "trip": {
    "title": "Япония, октябрь 2026", "country": "Япония", "file_suffix": "Япония",
    "start_date": "2026-10-16", "end_date": "2026-10-31",      // вылет из дома и возвращение
    "base_currency": "RUB", "local_currency": "JPY",
    "group": {"label": "2 чел.", "size": 2, "travelers": ["Ivan Petrov", "Anna Petrova"]},
    "extra": {"label": "+1", "size": 1, "travelers": ["Sergey Ivanov"]}  // size 0 — столбцы «+1» скрываются
  },
  "rates": [
    {"currency": "RUB", "rate": 1, "comment": "Базовая валюта"},
    {"currency": "JPY", "cbr_rate": 0.516121, "markup": 0.1, "rate_date": "2026-08-07", "source": "ЦБ РФ", "comment": "..."}
  ],
  "days": [   // каркас маршрута (фаза 2); в Excel не попадает, используется программой и проверками
    {"date": "2026-10-18", "city": "Токио", "overnight": "Токио", "theme": "Уэно и Акихабара",
     "places": ["Ueno Park", "Tokyo National Museum", "Akihabara"],
     "plan_en": "Tokyo National Museum, Ueno Park, Ameyoko, Akihabara.", "status": "Утверждено"}
  ],
  "flights":    [{"option", "details", "baggage", "currency", "price_pp", "qty_group", "qty_extra", "selected", "status", "comment"}],
  "hotels":     [{"city", "checkin", "checkout", "name", "area", "stars", "currency",
                  "price_group", "price_extra",            // цена номера за весь срок; 0 — этот номер не для группы / не для «+1»
                  "booking_group", "booking_extra", "link_group", "link_extra",
                  "selected", "status", "comment", "address", "address_local", "phone"}],
  "transport":  [{"id": "T01", "date", "segment", "type", "route", "option", "fare", "currency",
                  "calc_group": "2 × 610", "amount_group": 1220, "calc_extra": "1 × 610", "amount_extra": 610,
                  "selected", "status", "comment"}],
  "meals":      [{"id": "D17", "date", "area", "meal": "Ужин", "venue", "level", "why", "currency",
                  "food_pp": 2200, "drinks_group": 1600, "drinks_extra": 500, "selected", "status", "source", "aliases": []}],
  "attractions":[{"id": "A01", "date", "city", "name", "ticket", "currency", "price_pp", "qty_group", "qty_extra",
                  "selected", "status", "price_status", "comment", "aliases": []}],
  "other":      [{"category": "Связь", "item", "currency", "price", "qty_group", "qty_extra", "selected",
                  "in_reserve": true, "comment", "budget_stage", "budget_status", "budget_comment"}],
  "reserve":    {"share": 0.15, "include_flights": false, "comment": null, "budget_status": "Автоматически"},
  "budget":     {"flights": {"item", "stage", "status", "comment"}, "hotels": {...}, "transport": {...},
                 "meals": {...}, "attractions": {...}},   // подписи строк листа «Бюджет»; необязательно
  "budget_notes": [{"category": "Страховка", "item", "stage", "status": "Открыт", "comment", "amount_group", "amount_extra"}]
}
```

Правила:
- **ID вариантов.** Строки-альтернативы одного участка/приёма пищи/места имеют одинаковый `id`; выбран может быть только один (`Выбрано >1` — ошибка). Схема: `T01…` транспорт, `L<дд>` обед, `D<дд>` ужин, `S<дд>` перекусы, `A01…` места. Если ни один вариант не выбран — это опция («Не выбрано»).
- **Количества** `qty_group`/`qty_extra` по умолчанию равны размеру группы и «+1»; для строки только для «+1» поставь `qty_group: 0`.
- **Питание:** сумма группы = `food_pp × group.size + drinks_group`, «+1» = `food_pp × extra.size + drinks_extra`. Перекусы — `drinks_* = 0`.
- **Отели:** у номера, который не относится к «+1», `price_extra: 0` (и наоборот). Отели в разных строках для группы и «+1» — нормально.
- **Общие расходы с «+1»** (машина на всех): `amount_group`/`amount_extra` делятся по числу людей, расчёт виден в `calc_*` («2/3 × 2 000»).
- **`status`** — `Кандидат`, `Резерв`, `Выбран`, `Отклонён`, `Нужно проверить`, `Забронировано`, `Куплено`; причина — в комментарии. `selected` отвечает за расчёт, `status` — за состояние решения.
- **Пустая цена** у невыбранной строки допустима (нет данных — `status: "Нужно проверить"`); выдуманное число — нет.
- **`aliases`** — как место или ресторан названы в программе, если иначе (например, «Токийский национальный музей»): нужно для `check_consistency.py`.
- **Комментарии** — источник и дата проверки цены, условия отмены, что проверить. Это и есть «проверяемость».

## 3. Листы книги и формулы

Порядок листов: «Бюджет», «Курсы», «Перелеты», «Отели», «Транспорт», «Питание», «Достопримечательности», «Прочее». В каждой строке есть валюта; рубли считаются так: `сумма × VLOOKUP(валюта; Курсы!$A$2:$B$40; 2; ЛОЖЬ)`.

| Лист | Ключевые формулы |
|---|---|
| Курсы | `Курс = Курс источника × (1 + Надбавка)`; исходный курс ЦБ и надбавка хранятся отдельно |
| Перелеты | `RUB = ЕСЛИ(Выбран="Да"; Цена × Количество × курс; 0)` для группы и «+1» |
| Отели | `Ночей = Выезд − Заезд`; `RUB = Цена номера × курс` (видно и у кандидатов); итоги — `СУММЕСЛИ(Выбран; "Да"; …)` |
| Транспорт | Суммы группы и «+1» вводятся с текстом расчёта («2 × 610»); `RUB (выбранное) = ЕСЛИ(Выбран="Да"; Сумма × курс; 0)`; «Проверка выбора» по ID |
| Питание | `Сумма группы = Еда × размер группы + Напитки группы`; `Сумма «+1» = Еда × размер «+1» + Напитки «+1»`; RUB только для выбранных; «Проверка выбора» |
| Достопримечательности | `Сумма = Цена × Количество`; RUB только для выбранных; «Проверка выбора» |
| Прочее | `Сумма = Цена × Количество`; строка «Резерв» = доля × (Отели + Транспорт + Питание + Билеты + строки с «В резерв» = Да [+ Перелёты, если включены]) |
| Бюджет | Ссылки на итоги листов, строки «Прочего» по одной, заметки без сумм (например, «Страховка — Открыт»), «Резерв», «Итого» |

«Выбран» — выпадающий список Да/Нет; выбранные строки подсвечены зелёным, «Выбрано >1» — красным, «Не выбрано» — жёлтым. На листах «Транспорт», «Питание», «Достопримечательности» есть столбец «Статус». Столбцы «+1» скрыты, если `extra.size = 0`. Книга сохраняется уже пересчитанной LibreOffice (значения формул видны в превью); без LibreOffice формулы посчитает Excel при открытии.

## 4. Режимы работы с книгой

| Ситуация | Что делать |
|---|---|
| Книги ещё нет | `build_workbook.py --data trip_data.json --out Расчеты_<Страна>.xlsx` |
| Книга собрана скриптом и не менялась | Правь `trip_data.json`, пересобирай (резервная копия — в `архив/` автоматически) |
| Скрипт вернул код 3 (книгу меняли) | Режим сводок: таблица «Лист / Ячейка / Сейчас / Новое значение или формула / Почему»; адреса и значения — из `inspect_workbook.py`; те же изменения внеси в `trip_data.json` |
| Пользователь явно хочет вернуться к сборке | `xlsx_to_data.py --xlsx … --base trip_data.json --out trip_data.json` → показать итоги «до/после» → `build_workbook.py --force` |
| Книга открыта в Excel (код 4) | Попросить закрыть и повторить |
| Проект с собственным запретом на правку Excel (например, «Япония 2026») | Только сводки ячеек; скрипты сборки не запускать на рабочую книгу |

Если в книге пользователя добавлены строки, ссылайся в сводке на реальные адреса после вставки — поэтому адреса берутся из `inspect_workbook.py`, а не вычисляются.

## 5. Типовые операции

- **Сменить ресторан на день:** у старой строки `selected: "Нет"`, у новой `"Да"` (тот же `id`); в программе поменять основной и запасной вариант; `check_consistency.py`.
- **Новая цена отеля:** обновить `price_group`/`price_extra`, в `comment` — источник и дату; пересобрать; показать изменение итога.
- **Сдвинуть дату переезда:** даты `checkin`/`checkout` соседних отелей, новые цены (`ostrovok.py prices`), `days`, даты строк транспорта и питания; затем программа.
- **Новый курс:** `cbr_rate.py` → запись в `rates` → пересборка → итоги «до/после».
- **Проверка без записи:** `build_workbook.py --dry-run` — ошибки данных, покрытие ночей и итоги.
